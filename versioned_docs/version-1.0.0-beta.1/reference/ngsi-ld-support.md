# NGSI-LD subscription support

This page lists, member by member, what Aquila does with an NGSI-LD subscription as ETSI GS CIM 009 v1.9.1 defines it. The clause numbers refer to that version. Every entry has been checked against Scorpio.

| Status | Meaning |
| --- | --- |
| Supported | Set on create, shown, and editable |
| Create only | Set on create and shown. Read-only when editing, because Scorpio cannot change it |
| Read-only | Shown, never written by Aquila |
| Blocked | Disabled in the editor, because Scorpio rejects it |
| Kept | Not shown, but left as it is on the broker when Aquila edits the subscription |
| Planned | On the [roadmap](../roadmap.md) |

"Cannot be removed" means the value can be changed but not emptied once set. Scorpio has no working way to remove a member, as [broker compatibility](broker-compatibility.md) explains.

## Subscription (clause 5.2.12)

| Member | Status | Notes |
| --- | --- | --- |
| `id` | Read-only | Generated by the broker |
| `subscriptionName` | Supported | Required in the editor. A subscription without one is still listed and editable |
| `description` | Supported | Cannot be removed |
| `entities` | Partly | Selectors by `type` are supported, several at once. `id` and `idPattern` selectors are read-only: the list shows "+ id selectors", and the types are locked when editing so the selectors are not lost |
| `watchedAttributes` | Supported | Cannot be removed |
| `notificationTrigger` | Supported | Cannot be removed |
| `q` | Supported | The builder writes conditions combined with AND, and text mode accepts any query. Cannot be removed |
| `geoQ` | Partly | A circle (`Point` with `near;maxDistance`) is supported. Other shapes are kept but shown as no geo filter, and setting a circle replaces them |
| `scopeQ` | Supported | Cannot be removed |
| `temporalQ` | Kept | Planned, read-only |
| `csf` | Kept | |
| `isActive` | Supported | **Pause** and **Activate** in the list |
| `status` | Read-only | Active, paused or expired. Scorpio never reports `expired` |
| `expiresAt` | Supported | Cannot be removed |
| `throttling` | Supported | Cannot be removed. Scorpio ignores it, and the editor says so |
| `timeInterval` | Supported | "Every N seconds". Switching to or from "on change" is blocked when editing |
| `lang` | Create only | |
| `datasetId` | Kept | |
| `jsonldContext` | Create only | Scorpio returns the URL of its own copy |
| `expandValues`, `jsonKeys` | Supported | |
| `localOnly`, `splitEntities`, `ngsildConformance` | Kept | |

## NotificationParams (clause 5.2.14)

| Member | Status | Notes |
| --- | --- | --- |
| `format` | Supported | `normalized`, `concise` or `keyValues`. `simplified` is read as `keyValues`. New subscriptions start with `keyValues` |
| `attributes`, `pick` | Supported | "Only these attributes". Aquila sends `pick`, Scorpio stores it as `attributes`, and Aquila reads that back |
| `omit` | Supported | "Leave out" |
| `showChanges` | Supported | Not with `keyValues` |
| `sysAttrs` | Supported | |
| `join`, `joinLevel` | Blocked | Scorpio rejects them |
| `endpoint` | Partly | See [Endpoint](#endpoint-clause-5215) |
| `timesSent`, `timesFailed`, `lastNotification`, `lastSuccess`, `lastFailure`, `status` | Read-only | The **Delivery** column |

## Endpoint (clause 5.2.15)

| Member | Status | Notes |
| --- | --- | --- |
| `uri` | Supported | The notification URI. It has to be reachable from the broker |
| `accept` | Read-only | Always `application/json` on create |
| `receiverInfo` | Kept | Notification headers. Planned |
| `notifierInfo` | Kept | MQTT settings. Scorpio rejects it on create |
| `timeout`, `cooldown` | Kept | Scorpio rejects them on create |

## Operations (clause 5.8)

| Operation | Status | Notes |
| --- | --- | --- |
| Create subscription | Supported | |
| Update subscription | Supported | Sends only the members that changed. After a rejected update, Aquila reads the subscription again, since Scorpio may have applied part of it |
| Retrieve subscription | Supported | |
| Query subscriptions | Supported | Reads every page. No server-side paging or count |
| Delete subscription | Supported | After confirmation |
| Context source subscriptions (`/csourceSubscriptions`) | Not supported | |
| Tenants (`NGSILD-Tenant`) | Not supported | Planned, per broker |

## Notifications (clause 5.3)

Aquila does not receive notifications. The broker sends them straight to the subscription's notification URI. Receiving the standard notification (`subscriptionId`, `notifiedAt`, `data`) and storing it as alert history is planned for the short term, on the [roadmap](../roadmap.md).
